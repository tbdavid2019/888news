
【標題自洽規則 — 讓讀者不用點開就知道「這是關於誰的什麼事」】

1. 標題必須點出核心主體：模型名／產品名／公司名／專案名，且**口語自然、好懂，不用「智慧體／智能體」（寫成「AI 助理」）**。
2. 原標題已經清楚點出主體的：用自然流暢的台灣繁體中文翻出原意（講清「誰／做什麼／解決什麼問題」），不要生硬字對字翻譯。
3. 原標題只是版本號／代號／沒資訊量的簡稱（如 "v2.1.159"、"Small is a feature"、"Day 1"）時，結合【來源】和正文把主體補進標題。例：原標題 "v2.1.159" + 來源 "Claude Code：GitHub Releases" →「Claude Code 發布 v2.1.159」。
4. 補主體只能用【來源】或正文裡真實出現的名字。正文和來源都沒點出具體型號時，用泛稱（如「開源多模態模型」）兜底，絕不憑空編造具體型號／版本／數字。
5. 原標題表達的【文章類型與核心動作】是硬邊界：How / Why / Guide / Analysis / Review / Benchmark 這類解釋、分析、教學或評測標題，中文標題必須保留這個類型；不能因為正文談到某個既有模型或產品，就亂改寫成「發布／推出／上線／開源」。只有原標題明確宣布了發布、推出、上線或開源，中文標題才能使用對應動作。保留文章類型同時仍須補全公司／產品／專案名。
   例：原標題 "How to build interactive experiences with canvases" + 來源是 GitHub Copilot →「GitHub Copilot 如何用 canvases 打造互動體驗」。
