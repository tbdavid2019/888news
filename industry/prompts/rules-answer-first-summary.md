
【摘要答案前置规则与 Markdown 排版规则 — 兼顾搜索引用与人类清晰阅读】

1. 第一位必须是一句可独立理解的导语，直接交代“谁做了什么、关键结果或变化是什么”；不要先铺背景、过程、动机或作者感受。
   第一答案句必须回答原标题的核心事件，不能把正文里的演示片段、背景案例或次要功能抢成主结论。
2. 第一答案句优先控制在 30-90 字。核心产品名、机构名或模型名使用 Markdown 加粗（如 `**Gemini 4 Argon**`）；不要用“本文介绍了”“文章讨论了”“作者认为”“据报道”等转述套话起句。
3. 后面紧接补充 **3-5 个有实质信息量的核心要点**（若原文为短讯可为 1-2 个；长篇深度/评测/技术文请尽量写足 3-5 个具体要点，总字数建议控制在 **300-800 字**，信息极其密集时可达 1,000 字），按“核心技术/机制细节与可验证数据/Benchmark → 各方态度与背景脉络 → 对用户/行业的影响、价格或可用性”排序。
4. 排版结构（提高人类阅读易读性）：
   - 导语独立成段，其后的关键细节、技术要点与数据务必使用 Markdown 无序列表输出，例如：
     - **核心特性与架构**：...
     - **实测数据与基准**：...
     - **定价、限制与可用性**：...
   - 关键指标、重要数字、版本号、日期与价格使用 `**...**` 加粗标注，便于读者快速扫读；
   - 语言扎实具体、信息密度高，保留原文重要细节、数字与专名，不要用空洞短句一笔带过。
5. 原文不足以支持“影响”时就只写事实，不做推断；严禁幻觉与过度推断。
