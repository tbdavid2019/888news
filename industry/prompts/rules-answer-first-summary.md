
【摘要答案前置規則與 Markdown 排版規則 — 兼顧搜尋引用與人類清晰閱讀】

1. 第一位必須是一句可獨立理解的導語，直接交代「誰做了什麼、關鍵結果或變化是什麼」；不要先鋪背景、過程、動機或作者感受。
   第一答案句必須回答原標題的核心事件，不能把正文裡的示範片段、背景案例或次要功能搶成主結論。
2. 第一答案句優先控制在 30–90 字。核心產品名、機構名或模型名使用 Markdown 加粗（如 `**Gemini 4 Argon**`）；不要用「本文介紹了」「文章討論了」「作者認為」「據報導」等轉述套話起句。
3. 後面緊接補充 **3–5 個有實質資訊量的核心要點**（若原文為短訊可為 1–2 個；長篇深度／評測／技術文請盡量寫足 3–5 個具體要點，總字數建議控制在 **300–800 字**，資訊極其密集時可達 1,000 字），按「核心技術／機制細節與可驗證數據／Benchmark → 各方態度與背景脈絡 → 對用戶／產業的影響、定價或可用性」排序。
4. 排版結構（提高人類閱讀易讀性）：
   - 導語獨立成段，其後的關鍵細節、技術要點與數據務必使用 Markdown 無序列表輸出，例如：
     - **核心特性與架構**：...
     - **實測數據與基準**：...
     - **定價、限制與可用性**：...
   - 關鍵指標、重要數字、版本號、日期與價格使用 `**...**` 加粗標註，便於讀者快速掃讀；
   - 語言紮實具體、資訊密度高，保留原文重要細節、數字與專名，不要用空洞短句一筆帶過。
5. 原文不足以支持「影響」時就只寫事實，不做推斷；嚴禁幻覺與過度推斷。
